# GabFin S02/02a 契約切片結果

本單位完成 Task 2 的第一個可驗收切片：新 package、精確數值／UTC primitives，以及版本化的 TradePlan／StrategyIntent。**不是整個 Task 2 或 S02 完成，也沒有接上任何交易服務。**

## 實作與決定

- 新程式在 `services/gabfin/`，與 legacy `backend/` 命名空間分開。`pyproject.toml` 只 discovery `gabfin` packages，Python >=3.12、Pydantic 固定為本機已測試的 2.14.4。
- `contracts/common.py` 提供 Money、ExactDecimal、Ratio、UtcTimestamp、ContractModel／VersionedContract。Decimal JSON codec 使用字串；原生 float／bool／非有限值拒絕，保留負金額與小數精度；比例限 0..1。未設定任何交易風險數值或金額量化政策。
- 時間只接受 aware datetime／帶時區 ISO 字串，正規化成 UTC；拒絕 naive、數字 epoch 與純數字 epoch 字串。貨幣只驗證三個大寫字母的形狀，沒有宣稱驗證完整 ISO 清單或提供 FX。
- 使用者已選定 `StrategyIntent.side = long/short`，搭配必填 `position_effect = open/reduce/close`；不在此處轉成 buy/sell。主計劃 §2 的欄位表已同步這項確認，沒有改其他產品需求。
- `TradePlan` 必須有 `advisory=true`；兩類文件需明確 `kind`／`schema_version="1.0"`，以 discriminator 區分、禁止未知欄位，不能把 plan model／dump／JSON 直接驗成 StrategyIntent。
- `producer_scope="strategy:emit"` 只是 schema 標記，不是身分證明。Task 3 仍須驗證真正 principal／capability。`setup`／`invalidation` 在此切片是描述資料；接入 RiskService 前須補齊機器可驗證的策略／政策條件，不能把任意描述文字當成批准交易的規則。
- 過期 intent 仍可解析供歷史稽核；是否容許執行由後續 risk/context 時效檢查判斷，不在 parser 讀取當下時鐘。
