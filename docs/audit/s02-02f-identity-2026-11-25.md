## Engineering rulings and costs

- A Principal declaration may claim an invalid role/capability combination while remaining structurally valid. This is deliberate: the complete role ceiling matrix, trusted grants and resource ownership are Task 3 service decisions, not partially implemented here. Cost if a consumer trusts client metadata: unauthorized privilege; services must never treat parsed client Principal as authenticated identity.
- Explicit strategy role and strategy:emit capability align with existing StrategyIntent metadata. The declarations cannot promote research/chat into an authorized strategy producer.
- Resource owner is required UUID, with no inferred or shared/null owner. Cost: later public/shared resources need explicit modeling or trusted catalog resolution, rather than bypassing ownership by omitting it.
- Capabilities use explicit action names, without wildcard expansion. The enum does not assert any principal has those powers. New capability names must update contract/schema consumers deliberately.
- Existing ResearchRequest scope strings and StrategyIntent marker remain unchanged to preserve prior evidence; Task 3 boundary normalization/validation must reconcile them with trusted Capability values.
- No authentication, session issuance, authorize function, role ceiling matrix, credentials storage, resource lookup or API integration implemented. Policies still require registry verification and actual approval.
- Next bounded unit: job lease and budget reservation declarations. Other support models, aggregate schema, migrations and actual Task 3 authorization remain pending.
